## 2. Схема миграции маршрутов

Единая функция `normalizeHash()` вызывается при загрузке и на `hashchange`; редирект через `location.replace`, чтобы кнопка «назад» не зацикливалась.

| Старый адрес | Новый адрес |
|---|---|
| `#/home`, пусто | `#/today` |
| `#/<id>` темы, практики, проекта (`kind` = topic / practice / project) | `#/topic/<id>` |
| `#/<id>/<якорь>` | `#/topic/<id>/<якорь>` |
| `#/p1` … `#/p7` (обзор фазы) | `#/path/<номер фазы>` (чекпойнт-тест остаётся на странице обзора, открывается из узла «Чекпойнт») |
| `#/path` («Карта модулей») | `#/path` |
| `#/profile` | `#/profile` |
| `#/review` (карточки) | `#/profile/review` |
| `#/how`, `#/calibration`, `#/structure`, `#/lab` | `#/help/<id>` (раздел «Помощь» внутри «⋯») |
| `#/rabbit-holes` | `#/help/rabbit-holes`, заголовок → «Если застрял»; **id страницы не меняется** |
| `#/p7-applications` | `#/topic/p7-applications`; трекер откликов дополнительно открывается из «⋯» в drawer |
| `#/portfolio`, `#/risks`, `#/final` | `#/topic/<id>`; в «Пути» — узлы финиша |
| (новое) | `#/practice/<id>`, `#/ref`, `#/ref/<категория>/<запись>` |

Внутренние ссылки в `partials` (`[текст](#id)`) остаются; `Parser.link` будет сразу выдавать новые адреса, а старые продолжат работать через редирект.

## 3. Риски и решения

1. **Нестабильные идентификаторы прогресса.** `lid` блока = `pageId.тип+порядковый номер на странице`; ключи наград `q:lid:i`, `ide:lid`, `bug:lid:i`; id чекбокса = хэш его текста; id карточки = хэш вопроса. Вставка блока в середину страницы или правка текста чекбокса сломает сохранённый прогресс. **Правило для Этапов 4–8:** новые блоки — только в конец страницы, текст существующих чекбоксов и вопросов карточек не менять; перед Этапом 8 добавить в `labcheck.py` проверку снимка списка id.
2. **`lab.css` переопределяет `:root` — неон сейчас включён по умолчанию.** Решение (Этап 2): переопределения уйдут под `:root[data-vibe="neon"]`, а в спокойной теме старые переменные (`--bg`, `--card`, `--accent`…) станут алиасами на `--ds-*`. Так 91 страница старой вёрстки не ломается, а миграция на `.ds-*` идёт постепенно.
3. **Лаб-блоки — самодостаточные виджеты** со своим состоянием и без обратных вызовов. Для сессии практики нужны: разбиение квиза на вопросы (сохранив ключи `q:lid:i`, `qd:`, `qp:`), событие завершения блока (`lab:done` в местах `G.award`), полноэкранная раскладка IDE через CSS. Логику проверки и награды не менять.
4. **`app.js` — монолит на ~1000 строк в одном IIFE.** В начале Этапа 2 разнести на `src/app/*.js`, склеиваемые сборкой в том же порядке и в том же IIFE (поведение не меняется).
5. **Нет данных для новых экранов:** сложность, «чему научишься», тип узла (обязательная / дополнительная / проект / чекпойнт), «Что запомнить», зависимости. Решение: `src/meta.json` (pageId → поля); тип по умолчанию выводится из `kind`; время чтения считается при сборке по числу слов.
6. **Терминология.** В ТЗ «блокнот» = виджет `rabbit` (rabbit-holes). Принято допущение, что он и есть «блокнот»; если нужен отдельный свободный блокнот для заметок — скажи.
7. **Производительность.** Все 91 страница парсятся при запуске: 250 мс на десктопе, ~740 мс при замедлении CPU в 4 раза. Допустимо; ленивый парсинг — Этап 9.
8. **Gemini и `file://`.** Страница с `file://` делает запрос с origin `null`; поддержку CORS и актуальное имя модели нужно сверить с документацией Google на Этапе 6, а не по памяти.
9. **Устаревший текст в контенте** («кнопка с часами в шапке», «метка Ты здесь на карте пути», `rabbit-holes.md` в `00-common.md`, `rabbit-holes` в 7 ссылках) нужно обновить на Этапе 2 вместе с шапкой.

Таблица из п. 2 реализована; `#/practice/<id>` пока ведёт в тему (сессия — Этап 5), `#/path/<n>` показывает старый обзор фазы (дерево и дорожка — Этап 3), `#/ref` — пустая заглушка (Этап 7).

## 5. Этап 3 — страница «Путь»

Файлы: `src/app/20-path.js` (логика), `src/path.css` (стили), `src/meta.json` (необязательные темы и зависимости; build.py проверяет id), `tests/pathcheck.py`.

- Маршруты: `#/path[/n][?view=tree|track]`, n = 1..8 (8 = «Финиш»). Старые `#/p<n>` → `#/path/<n>`; чекпойнт доступен как `#/topic/p<n>`.
- Статус узла: явное значение `nodes[pid]` (todo/progress/done/skipped, ключ `csroad:nodes`, входит в экспорт) + вычисляемый (по чекбоксам страницы). `done`/`skipped` из явного значения главнее; вычисленный `done` главнее устаревшего явного.
- «Тема пройдена» пишется через настоящую карточку (`pageId.hash('__done__')`) синтетическим `change`, поэтому XP, карточки и закрытие фазы работают как раньше.
- Текущий узел для «Сегодня» и «Пути» определяет одна функция `currentNodePage()`.
- Награда: сундук в конце фазы даёт +100 XP один раз (`G.award('phase:n')`), когда закрыты критерии фазы. Анимация вспышки и конфетти учитывают `prefers-reduced-motion` и `data-motion="off"`; первое открытие «Пути» с существующим прогрессом ничего не празднует (`csroad:pathSeen`, не экспортируется).
- Дорожка: SVG-змейка фиксированной ширины 360px, центрируется (на узком экране переполнение уходит в поля).
- Риски: `META` подставляется build.py вместо `/*{{META}}*/` — маркер должен стоять один, без запасного значения.

## 6. Этап 4 — режим чтения темы

Файлы: `src/app/30-reader.js`, `src/reader.css`, `tests/readcheck.py`; правки в `app.js` (хук `readerAfterRender`, ключ `readpos` в экспорте) и `10-shell.js` (маршрут `#/practice/<id>`).

- Читалка — это пост-обработка уже отрендеренной страницы (kind = topic/practice/project), а не второй рендерер: `.content` оборачивается в `.rd-theory`, лаб-блоки (quiz, ide, ticket, cards, legacy, interview) **переносятся** (не пересоздаются) в `.rd-practice`. Поэтому lid, XP-ключи и состояние `lab` не меняются. `viz` и `compare` остаются в тексте как иллюстрации.
- Конец страницы: «Что запомнить» (если в теме есть `## Что запомнить`) → «Практика этой темы» → Microsoft Learn → «Тема пройдена» → предыдущая/следующая по порядку Пути (`pathPages(1..8)`).
- `#/practice/<id>` — временный режим: показывает только `.rd-practice`. Этап 5 заменит его сессией; страница без практики или чекпойнт → `#/topic/<id>`.
- Прогресс чтения — линия сверху (`.rd-prog`); позиция сохраняется в `csroad:readpos` (доля 0..1, не больше 120 тем, входит в экспорт). Подсказка «Вернуться к месту» не показывается при переходе по якорю.
- «Запустить»: кнопка появляется только у C#-фрагментов с `Console.`, которые интерпретатор реально выполнил без ошибок (проверка в idle, кэш `RD_RUN`); примеры с намеренной ошибкой компиляции кнопки не получают.
- Риски: размер `rem` на сайте 17px, поэтому в читалке размеры текста заданы в px; «В теме» берётся из первых трёх h2.

## 7. Этап 5 — сессия практики

Файлы: `src/app/40-session.js`, `src/session.css`, `tests/sessioncheck.py`; правки в `10-shell.js` (маршрут, `?at=`), `30-reader.js` (`readerPrune`, `compare` в практике).

- Маршрут `#/practice/<id>[?at=<lid>]`: полноэкранный слой `.sx` (шапка и нижняя панель скрыты классом `html.sx-open`, снимается в `showView → sessionDestroy`). Страница без практики и чекпойнт → `#/topic/<id>`; неизвестный `at` отбрасывается.
- Шаги = блоки страницы в исходном порядке (quiz по вопросу, ide/ticket, compare, legacy, interview, cards). Виджеты монтируются **теми же `LABUI` и lid**; сессия только наблюдает за их DOM (MutationObserver) и за `G.done`/`LabState` и рисует свою панель обратной связи. Логика проверки, XP, подсказки, ревью, карточки Лейтнера, ачивки не менялись.
- Что скрыто CSS: собственная панель вопроса (`.qfb`), точки прогресса, лид-абзац. Кнопка «Сдать на проверку» переименована в «Проверить».
- Итоги считаются из состояния: XP сессии = разница `G.st.xp`, точность по квизам (или по задачам, если квизов нет), «что повторить» — неверные вопросы и нерешённые задачи.
- Страница темы больше не монтирует блоки практики (`readerPrune` убирает их до `mountWidgets`).
- Исправлена ошибка Этапа 3: класс легенды `.lg` в `path.css` (ширина 28px) ломал размер кнопок `.ds-btn.lg`; теперь `.pt-lg`.

## 8. Этап 6 — Microsoft Learn и «Не понятно? Спроси ИИ»

Файлы: `src/links.json`, `src/app/50-ai.js`, `src/ai.css`, `tests/aicheck.py`, `tools/check_links.py`; правки в `build.py`, `30-reader.js`, `app.js`, `shell.html`.

**Ссылки Learn**
- Данные: `src/links.json` = `{pageId: [{title, path, why, type, verify?}]}`. `path` — относительно `learn.microsoft.com/<язык>/`. `type`: `tutorial | reference | guide | module | docs`. 3–6 ссылок на тему; у страниц-чекпойнтов, карьерных и сервисных страниц блока нет.
- `build.py` проверяет файл (id страниц существуют, 3–6 ссылок, поля заполнены, путь без хоста) и подставляет его в `var LINKS = /*{{LINKS}}*/;` (`30-reader.js`). Блоки `:::learn` из `partials/` удалены; парсер их по-прежнему понимает, но они больше не используются.
- Локаль берётся из `lang` (`ru-ru`/`en-us`); переключатель RU/EN в блоке и в меню один и тот же (`setLang`, `aria-pressed`). Ссылки: `target="_blank" rel="noopener noreferrer"`.
- `verify: true` — адрес статьи не подтверждён: ссылка ведёт на **поиск Learn по названию** и помечена «поиск по Learn». Проверка адресов — `python3 tools/check_links.py [--verify]` на машине с интернетом; исправленный `path` + убрать `verify`.

**ИИ-панель** (`50-ai.js`, всё внутри общего IIFE)
- Три входа: блок в конце темы, «?» справа от каждого h2 (добавляется последним шагом `readerAfterRender`, чтобы не попасть в оглавление), плавающая «Объяснить это» при выделении внутри `.rd-theory` (на touch — закреплена внизу; клавиатура: `Alt+E`).
- Панель — `DS.drawer` (справа на десктопе, нижний лист на мобильном). Промпт собирается по шаблону из ТЗ (`aiPromptText`), редактируется; пока промпт не правили руками, он пересобирается при вводе вопроса.
- Gemini: `POST …/v1beta/models/{модель}:streamGenerateContent?alt=sse`, ключ в заголовке `x-goog-api-key`. Модель по умолчанию — константа `AI_MODEL` (единственное место), переопределяется в «⋯ → ИИ-помощник → Модель». Стрим разбирается SSE-парсером; ошибки: нет ключа, сеть, 400/401/403 (ключ), 404 (модель), 429 (лимит), 5xx, пустой ответ, блокировка безопасностью; у всех есть «Повторить» или путь в настройки.
- Ответ рендерит собственный безопасный Markdown (`aiMd`: всё экранируется, ссылки только http(s), код через `highlight` с «Копировать»).
- Запасной путь без ключа: «Скопировать промпт» + «Открыть Gemini» (gemini.google.com/app в новой вкладке; автоподстановки нет).
- Хранение: ключ — `csroad:gemini-key` (+ необязательно `gemini-model`, `ai-warned`); эти ключи **не входят в `KEYS`**, значит не попадают в экспорт, и их нет в сборке (проверяет `aicheck.py`). История — `aihist` = `{pageId: [{id,t,q,sec,frag,a,via}]}` (в `KEYS`, т.е. экспортируется): ≤15 записей на тему, ≤350 тыс. символов всего (старые вытесняются), ответ ≤8000 символов. «Очистить» — в панели (по теме) и в Профиле (всё).
- Профиль: `WIDGETS.profile` обёрнут, добавлен раздел «Мои вопросы». «Сохранить в блокнот» кладёт запись в `rabbit` с полем `a` (ответ) и `src`; блокнот показывает «Ответ ИИ», `rabbit-holes.md` экспортирует его цитатой.
- Риски: прямой запрос из браузера зависит от CORS и доступности API в регионе; из песочницы реальный Gemini не вызывался (в тестах сеть подменена `page.route`).

## 9. Этап 7 — Справочник C#

Файлы: `partials/ref-*.md`, `src/app/60-ref.js`, `src/ref.css`, `tests/refcheck.py`, `tools/verify_ref.py`; правки в `build.py`, `src/app.js`, `10-shell.js`, `30-reader.js`, `shell.html`.

**Хранение и сборка**
- Источник — `partials/ref-<категория>-<NN>-<имя>.md` (пример: `ref-a-05-patterns.md`). Файлы `ref-*` **не** страницы курса: `pages()` их пропускает, их собирает `load_refs()`.
- Разметка: `@@refcat cat="A" title=".." lead=".."` (тело — обзор категории, ≤ 2500 слов) и `@@ref id=".." cat="A" title=".." cs=".." [net cx mem danger tags topic related learn table]` (тело — вводный абзац и семь разделов `## Название {#syntax|semantics|internals|complexity|versions|pitfalls|examples}`). Раздел «Связанное» с обратными ссылками добавляет приложение.
- `topic` — id страниц курса (из них строится блок «Подробнее в справочнике» в теме и обратные ссылки), `related` — id других записей, `learn` — `путь::Название` (с `?` в начале — адрес не подтверждён, ведёт на поиск Learn).
- Сборка: индекс (`id, cat, title, lead, бейджи, tags, topic, related, learn`) подставляется в `var REF = /*{{REFIDX}}*/;`; тексты статей лежат в `<script type="text/x-ref" data-id>` и разбираются Markdown-парсером лениво при открытии. Предупреждения (не ошибки): объём 300–1200 слов, неизвестный `related`/`topic`; с `--strict-ref` они становятся ошибками. Идентификатор записи должен быть длиннее одной буквы, чтобы не пересекаться с адресами категорий.
- Расширения парсера: `~~~csharp @nocheck|@norun` в заголовке блока; контейнер `:::sortable Заголовок` (таблица с сортировкой по клику и фильтром, `aria-sort`, числовая сортировка для `O(…)` и чисел).

**Маршруты** `#/ref`, `#/ref/<кат>`, `#/ref/<кат>/<запись>[/<раздел>]`; адрес `#/ref/<запись>` приводится к полному. Клавиша `R` и пункт «Справочник» открывают раздел. Постоянные якоря — `id="h-<раздел>"`; рядом с каждым h2/h3 кнопка «Скопировать ссылку на раздел» (`aiCopyText`).

**Интерфейс** (`60-ref.js`): указатель слева с фильтром по заголовкам и тегам (на ≤ 900 px — шторка `DS.drawer`), хлебные крошки, бейджи (C#, .NET, время, память, «ловушка»), оглавление справа с подсветкой текущего раздела, prev/next, блок «Связанное» (справочник / курс / Microsoft Learn). Глобальный поиск (`Ctrl+K`) индексирует и статьи справочника по разделам (`refSearchItems`).

**Запуск примеров.** Кнопка «Запустить» (как в читалке) показывается у C#-блока с `Console.`, который проходит встроенный интерпретатор `CS.run`; иначе подпись «не запускается в браузерной IDE». Корректность самих примеров проверяет `tools/verify_ref.py` настоящим компилятором .NET (см. ниже).

**Проверка примеров** (`tools/verify_ref.py`, нужен `dotnet` в PATH, по умолчанию net10.0, C# `latest`): каждый ```` ~~~csharp ```` блок компилируется как отдельная программа (top-level statements; типы — в конце); если сразу за ним идёт `~~~console`, программа запускается и вывод сравнивается. `--fill` заполняет блоки `~~~console` с единственной строкой `?` реальным выводом (потом прочитать глазами), `--force` игнорирует кэш (`tools/.cache`, не в git). Утверждения про версии языка проверялись компиляцией с `LangVersion`.

**Тесты** `tests/refcheck.py`: маршруты и канонизация, структура статьи, якоря и копирование ссылки, указатель и фильтр, поиск `Ctrl+K`, сортируемая таблица, метки запуска, обратная ссылка из темы, все записи (7 разделов, примеры, без битых ссылок), мобильный режим 360 px и шторка, ошибки консоли.

## 10. Этап 8 — расширение теории по фазам

Файлы: `partials/1x-…`, `2x-…` и далее (тела страниц тем), `tools/verify_theory.py`, `tools/rewrite_page.py`, `tests/theorycheck.py`, `tests/theory_baseline.json`, отчёт — `docs/STAGE8-REPORT.md`.

**Шаблон темы** (семь `##`-разделов в таком порядке, затем `## Практика` с чекбоксами): «Зачем это нужно» → «Интуиция и аналогия» → «Основная теория по шагам» (внутри `###`-шаги) → «Как это работает под капотом» → «Типичные ошибки и ловушки» → «Вопросы с собеседований» (`:::spoiler`, ≥ 5, с ловушкой) → «Что запомнить» (читалка выносит его в конец страницы). Блок `:::why` остаётся до первого `##`. Объём — 1500–3500 слов прозы без кода (`theorycheck.py` считает). Блоки практики (`:::quiz/ide/ticket/compare/cards/legacy`) по-прежнему приходят из `@@append` в `5x-lab-*.md` и показываются только в сессии практики.

**Сохранность прогресса.** Ключ чекбокса = `<id страницы>.<хэш текста пункта>`, поэтому тексты пунктов «Практики» менять нельзя; `theory_baseline.json` хранит тексты чекбоксов всех страниц на момент начала этапа, `theorycheck.py` проверяет, что они на месте. Идентификаторы страниц и `{#якоря}` (`#pass` в `p1-types`) не меняются.

**Примеры кода.** Блок `~~~csharp`, за которым сразу идёт `~~~console`, компилируется и запускается настоящим .NET (`tools/verify_theory.py`; `--fill` заполняет `?`; кэш — `tools/.cache/theory-verified.json`); вывод читается глазами. Фрагменты без вывода и `@nocheck` не проверяются. Из-за `InvariantGlobalization` проверка идёт в инвариантной культуре: формат `N2` даёт `1,010.00`; на русской локали будет `1 010,00` — в тексте это оговорено. Нельзя полагаться на вывод, зависящий от времени, JIT и сборщика мусора (аллокации выбрасываются, если результат не используется): примеры печатают булевы сравнения («выделил больше в 100 раз») или применяют `NoInlining`/приёмники.

**Инструмент замены.** `python3 tools/rewrite_page.py <id> <файл.md>` заменяет тело страницы в её partial (строка `@@page` сохраняется).
