Операторы `+`, `-`, `*` складывают, вычитают и перемножают числа, а унарные `+` и `-` оставляют или меняют знак; результат всегда имеет тип, выбранный по правилам числового повышения.

## Синтаксис {#syntax}

~~~csharp @nocheck
x + y        // сложение
x - y        // вычитание
x * y        // умножение
+x           // унарный плюс (возвращает x, но с повышением типа)
-x           // унарный минус (смена знака)
~~~

Деление `/`, остаток `%` и инкремент с декрементом вынесены в отдельные записи: [деление и остаток](#/ref/a/op-division), [++ и −−](#/ref/a/op-incdec).

## Семантика {#semantics}

Оба операнда сначала приводятся к общему типу по правилам **бинарного числового повышения**. Порядок проверки такой:

1. если один из операндов `decimal` — другой должен быть целым или `decimal` (смешивать `decimal` с `float` или `double` нельзя, это ошибка компиляции);
2. иначе, если один из операндов `double` — оба становятся `double`;
3. иначе, если один из операндов `float` — оба становятся `float`;
4. иначе, если один из операндов `ulong` — другой должен быть беззнаковым (смешивать `ulong` со знаковыми нельзя);
5. иначе, если один `long` — оба `long`; если `uint` и знаковый — оба `long`; если один `uint` — оба `uint`;
6. во всех остальных случаях (`byte`, `sbyte`, `short`, `ushort`, `char`, `int`) оба операнда становятся `int`.

Из пункта 6 следует главное правило: **арифметика над типами уже `int` всегда даёт `int`**. Поэтому `byte + byte` — это `int`, и обратно в `byte` без явного приведения результат не положить.

Унарный минус над `uint` повышает тип до `long`, а над `ulong` не определён. Для `int.MinValue` унарный минус возвращает то же значение (переполнение, в `unchecked`-контексте молча).

Операнды вычисляются слева направо, побочных эффектов сам оператор не имеет. Для `string` оператор `+` означает [конкатенацию](#/ref/a/op-string-concat), для делегатов — объединение.

## Под капотом {#internals}

Компилятор превращает `a + b` в одну IL-инструкцию `add`, `sub` или `mul` (в контексте `checked` — `add.ovf`, `sub.ovf`, `mul.ovf`, см. [checked и unchecked](#/ref/a/op-overflow)). Для `byte`, `short` и `char` значения на стеке вычислений IL и так занимают 32 бита, поэтому повышение до `int` ничего не стоит.

JIT на x64 превращает сложение в `add` или `lea`, умножение на константу — в сдвиги и сложения или `imul`. Константные выражения (`2 * 3600`) вычисляет сам компилятор, в IL остаётся готовое число; переполнение в константном выражении — ошибка компиляции.

`decimal` — не аппаратный тип: его операции выполняет код библиотеки, поэтому они заметно медленнее `double`. Числа хранятся в значениях, аллокаций арифметика не создаёт.

## Сложность {#complexity}

Для встроенных числовых типов — `O(1)` по времени и памяти. Для `decimal` время тоже константно, но с большим множителем. Для `BigInteger` стоимость растёт вместе с размером числа (умножение дороже сложения).

## Версии {#versions}

- C# 1.0 — все операторы.
- C# 11 / .NET 7 — для обобщённого кода появились интерфейсы обобщённой математики (`INumber<T>`, `IAdditionOperators<,,>`), и `a + b` работает над `T`, ограниченным такими интерфейсами. Пользовательские операторы можно объявлять с модификатором `checked`.

## Ловушки {#pitfalls}

**`byte + byte` — это `int`.**

~~~csharp @nocheck
byte a = 100, b = 100;
byte c = a + b;          // ❌ ошибка CS0266: нет неявного int → byte
byte d = (byte)(a + b);  // ✅ явное приведение (200 влезает)
~~~

**Вещественные числа не точны.** `0.1 + 0.2` в `double` не равно `0.3`; для денег нужен `decimal` (подробнее в [NaN и Infinity](#/ref/a/op-float-special)).

**Константы подчиняются своим правилам.** `1u - 2` — это `uint - uint`: константа `2` неявно приводится к `uint`, и компилятор остановит выражение ошибкой CS0220 (переполнение). С переменными `uint` и `int` результат — `long`.

**`decimal` и `double` не смешиваются** — `1.5m + 1.5` не скомпилируется; приводите явно и осознанно.

**Тип результата определяется операндами, а не переменной слева.** `long big = max + 1;` при `int max` посчитает сумму в `int` (переполнение), а потом расширит. Если и `max` — константа, компилятор остановит такую запись ошибкой CS0220.

## Примеры {#examples}

~~~csharp
byte a = 100, b = 100;
var sum = a + b;                          // int
Console.WriteLine(sum.GetType().Name);    // Int32
Console.WriteLine((byte)(a + b));         // 200

uint u = 1; int i = 2;
Console.WriteLine((u - i).GetType().Name);    // Int64: uint и int → long
Console.WriteLine(u - i);                     // -1 (а не 4294967295)
Console.WriteLine(0.1 + 0.2 == 0.3);          // False
Console.WriteLine(0.1m + 0.2m == 0.3m);       // True

int max = int.MaxValue;
long big = max + 1;                           // сложение в int (молча переполняется), затем расширение
Console.WriteLine(big);
long right = max + 1L;                        // сложение уже в long
Console.WriteLine(right);
~~~
~~~console
Int32
200
Int64
-1
False
True
-2147483648
2147483648
~~~

@@ref id="op-division" cat="A" title="Деление и остаток (/ и %)" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="деление остаток modulo remainder DivideByZeroException целочисленное деление отрицательные truncation fmod divrem" topic="p1-syntax,p1-types" related="op-arithmetic,op-overflow,op-float-special" learn="dotnet/csharp/language-reference/operators/arithmetic-operators::Оператор деления"
Оператор `/` делит, а `%` возвращает остаток от деления; для целых чисел `/` отбрасывает дробную часть (в сторону нуля), для вещественных даёт точное дробное значение.

## Синтаксис {#syntax}

~~~csharp @nocheck
a / b        // частное
a % b        // остаток
a /= b;  a %= b;   // составные формы
~~~

Операнды подчиняются [числовому повышению](#/ref/a/op-arithmetic): `int / int` — `int`, `int / double` — `double`.

## Семантика {#semantics}

**Целочисленное деление** отбрасывает дробную часть, округляя к нулю: `7 / 2 == 3`, `-7 / 2 == -3` (не `-4`).

**Остаток** определяется тождеством `(a / b) * b + (a % b) == a`. Отсюда знак остатка всегда совпадает со знаком делимого: `-7 % 3 == -1`, `7 % -3 == 1`. Это отличается от «математического» модуля в Python, где результат берёт знак делителя.

**Деление на ноль:**

| Выражение | Результат |
|---|---|
| `int / 0`, `int % 0` | `DivideByZeroException` |
| литеральное `x / 0` | ошибка компиляции CS0020 |
| `double / 0.0` | `Infinity`, `-Infinity` или `NaN` (для `0.0/0.0`), исключения нет |
| `decimal / 0` | `DivideByZeroException` |

**Единственный переполняющийся случай** целочисленного деления — `int.MinValue / -1` (результат `2147483648` не помещается в `int`). Он бросает `OverflowException` независимо от `checked`/`unchecked`.

**Остаток для `double`** считается как `a - b * truncate(a / b)`: `5.5 % 2 == 1.5`. Это не то же самое, что `Math.IEEERemainder`, которое округляет частное к ближайшему целому.

## Под капотом {#internals}

IL содержит инструкции `div` и `rem`. На x86/x64 целочисленному делению соответствует `idiv`/`div` — одна из самых медленных арифметических инструкций CPU (десятки тактов на старых процессорах, заметно меньше на современных). Поэтому JIT старается её избежать: деление на константу заменяется умножением на «магическое число» и сдвигами, деление беззнакового на степень двойки — сдвигом. Знаковое деление на степень двойки требует поправки для отрицательных чисел, чтобы сохранить округление к нулю.

Проверку делителя на ноль и на `-1` JIT вставляет сам, если не может доказать безопасность; именно оттуда берутся `DivideByZeroException` и `OverflowException`.

## Сложность {#complexity}

`O(1)`. На практике деление дороже сложения и умножения; в горячих циклах его выносят за цикл или заменяют умножением на обратную величину (для вещественных — с оглядкой на точность).

## Версии {#versions}

- C# 1.0 — `/` и `%`.
- .NET 7 — для целых типов есть `int.DivRem(a, b)`, возвращающий частное и остаток кортежем за одну операцию.
- C# 11 — пользовательские `checked`-операторы деления.

## Ловушки {#pitfalls}

**Среднее из целых.**

~~~csharp
int sum = 7, count = 2;
double bad = sum / count;            // ❌ деление целых: 3, потом 3.0
double good = (double)sum / count;   // ✅ 3.5
Console.WriteLine($"{bad} {good}");
~~~
~~~console
3 3.5
~~~

**Отрицательные индексы по кругу.** `index % length` для отрицательного `index` даёт отрицательный остаток — выход за границы массива. Нужна поправка: `((index % n) + n) % n`.

**Проценты в целых.** `part / total * 100` даёт 0, пока `part < total`; умножайте сначала: `part * 100 / total` (следите за переполнением).

## Примеры {#examples}

~~~csharp
Console.WriteLine(7 / 2);        // 3
Console.WriteLine(-7 / 2);       // -3
Console.WriteLine(-7 % 3);       // -1
Console.WriteLine(7 % -3);       // 1
Console.WriteLine(5.5 % 2);      // 1.5
Console.WriteLine(1.0 / 0);      // Infinity
Console.WriteLine(-1.0 / 0);     // -Infinity

int n = 5;
Console.WriteLine(((-1 % n) + n) % n);   // 4: «круговой» индекс
Console.WriteLine(int.DivRem(17, 5));    // (3, 2)

try { int zero = 0; Console.WriteLine(10 / zero); }
catch (DivideByZeroException e) { Console.WriteLine(e.GetType().Name); }

try { int m = int.MinValue, d = -1; Console.WriteLine(m / d); }
catch (OverflowException e) { Console.WriteLine(e.GetType().Name); }
~~~
~~~console
3
-3
-1
1
1.5
Infinity
-Infinity
4
(3, 2)
DivideByZeroException
OverflowException
~~~
