Проект Фазы 4 превращается из «работает у меня» в «работает и это доказано»: тесты, CI, асинхронная обработка. Именно так выглядит реальная работа джуна в первые месяцы — дорабатывать и покрывать тестами существующий код.
:::

## Вариант А (рекомендуемый): доработка API Фазы 4

### Тесты

- [ ] Проект `*.Domain.Tests`: тесты всех доменных правил (25+)
- [ ] Проект `*.Application.Tests`: тесты сервисов/обработчиков с моками или фейками (15+)
- [ ] Проект `*.Api.Tests`: интеграционные тесты через `WebApplicationFactory` + Testcontainers (5–10): сценарий, валидация, 401/403, 404, 409
- [ ] Каждый найденный за фазу баг закрыт тестом, который его воспроизводит
- [ ] Тесты не зависят от текущего времени, порядка запуска и друг от друга

### Асинхронность и фон

- [ ] Все цепочки асинхронны сверху донизу, `CancellationToken` протянут до EF Core
- [ ] Уведомления (назначение задачи, упоминание в комментарии) уходят через `Channel` + `BackgroundService`, эндпоинт отвечает сразу
- [ ] Периодическая задача: напоминания о просроченных задачах (`PeriodicTimer`)
- [ ] Ошибка одного задания не останавливает воркер; корректная остановка по `stoppingToken`

### Паттерны и инженерия

- [ ] Минимум один паттерн применён по реальной причине и описан в README (проблема → решение → результат)
- [ ] GitHub Actions: build + test на каждый push и PR, значок в README
- [ ] Работа через PR с описанием; `main` защищена

## Вариант Б: новый сервис с фоновой обработкой

Сервис обработки файлов: пользователь загружает CSV с задачами → API сразу отвечает `202 Accepted` с id импорта → фоновый воркер разбирает файл, валидирует строки, сохраняет корректные, собирает отчёт об ошибках → `GET /imports/{id}` показывает статус (`Queued`, `Processing`, `Done`, `Failed`) и отчёт.

- [ ] Ограничение размера файла и проверка формата на входе
- [ ] Статус импорта хранится в базе (переживает перезапуск)
- [ ] Ограничение параллельных импортов (`SemaphoreSlim` или один воркер)
- [ ] Те же требования к тестам и CI, что в варианте А

## Как считать «осмысленные» тесты

Тест засчитывается, если на вопрос «какой баг он поймает?» есть конкретный ответ. Примеры:

| Тест | Какой баг ловит |
|---|---|
| `Complete_AlreadyDone_ThrowsConflict` | повторное закрытие перезапишет дату завершения |
| `Assign_NotProjectMember_Throws` | задачу назначат постороннему человеку |
| `Register_DuplicateEmail_Returns409` | два аккаунта на один email |
| `GetTasks_OtherUsersProject_Returns404` | утечка чужих данных |
| `FinePolicy_100DaysLate_IsCapped` | штраф без верхней границы |

## Граничные случаи для фона

- [ ] Очередь заполнена → эндпоинт ждёт или отвечает `503` (реши и опиши)
- [ ] Отправка уведомления упала → ошибка залогирована с контекстом, остальные задания обрабатываются
- [ ] Остановка приложения во время обработки → воркер завершается без необработанных исключений
- [ ] Напоминание не отправляется дважды за одни сутки об одной задаче
