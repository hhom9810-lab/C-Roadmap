? Чем `struct` отличается от `class` при передаче в метод? #memory

- Структуры всегда в куче
- Классы копируются
= Изменяемые структуры — источник сюрпризов.

? Зачем реализуют `IDisposable`? #memory
+ Чтобы детерминированно освободить неуправляемые ресурсы (соединения, файлы, дескрипторы) через `using`, не дожидаясь GC
- Чтобы ускорить GC
- Для сериализации
- Для сравнения объектов
= GC освобождает память, но не знает, когда закрыть соединение с БД.

? Что вернёт `new List<int>{1,2,3}.Select(x => x * 2)` без перебора? #net
+ Ленивую последовательность: вычисления ещё не выполнены
- Список 2,4,6
- Массив
- Исключение
= Выполнение отложено до перебора.

? Чем `==` отличается от `Equals` для ссылочных типов по умолчанию? #oop
+ `==` сравнивает ссылки (если не перегружен), `Equals` по умолчанию — тоже ссылки, но переопределяется для сравнения значений; `string` и `record` ведут себя по значению
- Ничем и всегда сравнивают значения
- `Equals` всегда быстрее
- `==` работает только для чисел
= Для своих типов, используемых в `Dictionary`/`HashSet`, переопредели `Equals` и `GetHashCode` вместе.

@tests
~~~csharp
class T
{
    public static void Run()
    {
        Assert.True(Solver.IsPalindrome("А роза упала на лапу Азора"), "фраза с пробелами и регистром");
        Assert.True(Solver.IsPalindrome("A man, a plan, a canal: Panama"), "знаки препинания");
        Assert.False(Solver.IsPalindrome("hello"), "не палиндром");
        Assert.True(Solver.IsPalindrome(""), "пустая");
        Assert.True(Solver.IsPalindrome("a"), "один символ");
        Assert.False(Solver.IsPalindrome("ab"), "два разных");
    }
}
~~~
@hint
Два указателя с краёв: пропускай символы, для которых `!char.IsLetterOrDigit`, сравнивай `char.ToLower`. Без создания новой строки — O(1) памяти.
@solution
~~~csharp
using System;

public static class Solver
{
    public static bool IsPalindrome(string s)
    {
        int i = 0, j = s.Length - 1;
        while (i < j)
        {
            if (!char.IsLetterOrDigit(s[i])) { i++; continue; }
            if (!char.IsLetterOrDigit(s[j])) { j--; continue; }
            if (char.ToLower(s[i]) != char.ToLower(s[j])) return false;
            i++;
            j--;
        }
        return true;
    }
}
~~~
@why
Интервьюер ждёт не только рабочий код: назови сложность (O(N) время, O(1) память), перечисли крайние случаи (пустая строка, один символ, только знаки) и скажи, как протестируешь.
:::

:::interview == и Equals
@q В чём разница между `==`, `Equals` и `ReferenceEquals`? Что будет, если переопределить `Equals`, но не `GetHashCode`?
@trap Целостность знаний: типы значения/ссылки, строки, контракт Equals/GetHashCode и работа словарей.
@answer
`ReferenceEquals` сравнивает ссылки. `Equals` — виртуальный метод; по умолчанию для классов тоже сравнивает ссылки, для структур — значения полей (через рефлексию, медленно). `==` — оператор: по умолчанию ссылки для классов, но перегружен для `string` (по значению), `record`, чисел. Если переопределить `Equals`, но не `GetHashCode`, равные объекты получат разные хэши и «потеряются» в `Dictionary`/`HashSet`: поиск идёт по хэшу, потом по `Equals`. Правило: равные объекты ⇒ одинаковый хэш; `GetHashCode` строить на неизменяемых полях. Удобнее использовать `record` или `HashCode.Combine`.
@fail «Equals сравнивает значения, == — ссылки» — верно лишь для отдельных типов, а не как общее правило.
@follow Почему изменяемое поле в `GetHashCode` опасно?
:::

:::interview IDisposable и finalizer
@q Зачем нужен `IDisposable`, чем он отличается от финализатора и как работает `using`?
@trap Понимает ли кандидат разницу между управляемой памятью и неуправляемыми ресурсами.
@answer
GC освобождает управляемую память, но не знает, когда закрыть файл, сокет или соединение с БД. `IDisposable.Dispose()` — детерминированная очистка; `using` гарантирует вызов `Dispose` даже при исключении (разворачивается в `try/finally`). Финализатор (`~Class`) — запасной механизм для неуправляемых ресурсов: вызывается GC неизвестно когда и замедляет сборку (объект переживает лишнюю сборку), поэтому его реализуют редко, а при наличии — вызывают `GC.SuppressFinalize` из `Dispose`. Для обёрток над неуправляемыми ресурсами лучше `SafeHandle`.
@fail «`Dispose` освобождает память объекта» — нет, память освобождает GC.
@follow Что произойдёт, если не вызвать `Dispose` у `SqlConnection`?
:::

:::interview Как работает сборщик мусора
@q Расскажите про поколения в GC и почему не нужно вызывать `GC.Collect()`.
@trap Понимание generational GC, LOH и стоимости ручных вмешательств.
@answer
Объекты делятся на поколения 0, 1, 2. Новые объекты — в gen 0, который собирается часто и дёшево; выжившие переходят в gen 1, затем в gen 2. Гипотеза: большинство объектов умирает молодыми. Крупные объекты (≥85 КБ) попадают в Large Object Heap, собираемый вместе с gen 2 и без уплотнения по умолчанию — частые крупные аллокации приводят к фрагментации. Ручной `GC.Collect()` обычно вредит: нарушает эвристики, продвигает живые объекты в старшие поколения и вызывает паузы. Лучше уменьшать аллокации (пулы, `Span<T>`, `StringBuilder`) и освобождать ресурсы через `Dispose`.
@fail «GC удаляет объекты, когда нет места» — нет описания поколений и стоимости сборки.
@follow Что такое утечка памяти в .NET, если есть GC? (Объекты, на которые остались ссылки: события, статические коллекции, кэши.)
:::

:::cards Банк вопросов
Интернирование строк :: Одинаковые строковые литералы указывают на один объект; строки из рантайма — нет.
new vs override :: override — полиморфизм; new скрывает и зависит от типа переменной.
struct vs class :: struct — значение (копия), class — ссылка; struct не вызывает GC-давление в стеке, но копируется.
IDisposable :: Детерминированная очистка неуправляемых ресурсов; using = try/finally.
Equals и GetHashCode :: Переопределяй вместе; хэш на неизменяемых полях.
Поколения GC :: gen0 → gen1 → gen2; LOH для крупных объектов.
Boxing :: Упаковка значения в object — аллокация в куче; избегай в горячих путях.
Утечка в .NET :: Живые ссылки (события, статические кэши) не дают GC освободить объекты.
:::

## Итоговый тест курса {#lab}

:::quiz Финальный экзамен: C# → Junior .NET
? Что выведет код? #net
| var list = new List<int> { 1, 2, 3 };
| foreach (var x in list) { if (x == 2) list.Add(4); }
+ `InvalidOperationException`: коллекция изменена во время перебора
- Добавит 4 и закончит
- Бесконечный цикл
- Ничего
= Перечислитель `List<T>` проверяет версию коллекции.

? Метод `async Task<int> A()` вызван как `int r = A().Result;` в ASP.NET (классический, с контекстом синхронизации). Риск? #async
+ Deadlock: поток ждёт задачу, а продолжению нужен именно он
- Нет рисков
- Утечка памяти
- Потеря данных
= Решение — `await` и «async all the way».

? Какой запрос быстрее на таблице в 10 млн строк при индексе по `CreatedAt`? #sql
+ `WHERE CreatedAt >= '2024-01-01' AND CreatedAt < '2024-02-01'`
- `WHERE YEAR(CreatedAt) = 2024 AND MONTH(CreatedAt) = 1`
- `WHERE CAST(CreatedAt AS text) LIKE '2024-01%'`
- Все одинаково
= Функция над столбцом мешает использовать индекс.

? Что из этого нарушает принцип единственной ответственности? #oop
+ Класс, который читает БД, считает бизнес-правила и формирует PDF
- Класс с несколькими методами одной темы
- Класс с интерфейсом
- Класс с конструктором
= Причина изменения должна быть одна.

? Singleton-сервис принимает `DbContext` в конструкторе. Что не так? #web
+ Scoped-зависимость «застревает» в синглтоне: DbContext не потокобезопасен и накапливает данные
- Ничего
- Не скомпилируется всегда
- Это быстрее
= Зависимость не должна жить дольше потребителя.

? Почему `List<T>.Contains` в цикле по N элементам — потенциальная проблема? #bigo
+ Каждый вызов O(N), итого O(N²); `HashSet` даст O(1)
- Это всегда быстро
- Contains бросает исключение
- Это зависит от версии .NET
= Выбор структуры данных — первое, на что смотрят при оптимизации.

? Чем боксинг опасен в горячих путях? #memory
+ Каждая упаковка — аллокация в куче и давление на GC
- Ничем
- Он запрещён
- Приводит к исключению
= Используй generic-коллекции вместо `ArrayList`/`object`.

? Что делает `SaveChanges()` при изменении двух отслеживаемых сущностей? #net
+ Отправляет обе операции одной транзакцией
- Только первую
- Каждую в отдельной транзакции
- Ничего без `Update()`
= Всё или ничего — так работает единица работы.

? Что лучше для тестирования метода, зависящего от текущего времени? #test
+ Внедрить `IClock`/`TimeProvider` и подставить фиксированное время
- Вызвать `Thread.Sleep`
- Запускать тест в нужный час
- Не тестировать
= Недетерминированные зависимости прячь за интерфейсом.

? Какая команда безопасно «отменяет» опубликованный коммит? #test

- `git reset --hard` с force-push в общую ветку
- Удаление репозитория
- `git rebase` общей ветки
= Revert не переписывает историю.
