:::spoiler Ответ к 18
~~~sql
SELECT b.genre, count(l.id) AS loans
FROM books b
LEFT JOIN loans l ON l.book_id = b.id
GROUP BY b.genre
ORDER BY loans DESC, b.genre;
~~~

~~~text
  genre  | loans
---------+-------
 Роман   |     6
 Повесть |     1
 Поэма   |     0
 Учебник |     0
~~~

Ключевое: `LEFT JOIN` и `count(l.id)`, а не `count(*)`.
:::

:::spoiler Ответ к 20
~~~sql
SELECT r.reader_type, round(avg(l.returned_at - l.loaned_at), 1) AS avg_days
FROM loans l
JOIN readers r ON r.id = l.reader_id
WHERE l.returned_at IS NOT NULL
GROUP BY r.reader_type
ORDER BY r.reader_type;
~~~

~~~text
 reader_type | avg_days
-------------+----------
 student     |     15.7
 teacher     |     26.0
~~~

В PostgreSQL разность двух `DATE` — целое число дней.

## Подзапросы, CTE, окна (25–30)

- [ ] 25. Книги новее среднего года издания
- [ ] 26. Последняя взятая книга каждого читателя
- [ ] 27. Количество выдач по месяцам и нарастающий итог

- [ ] 29. Доля каждого жанра в общем числе выдач (в процентах)
- [ ] 30. Читатели, взявшие больше книг, чем в среднем берёт читатель

:::spoiler Ответ к 26
~~~sql
WITH ranked AS (
    SELECT r.full_name, b.title, l.loaned_at,
           row_number() OVER (PARTITION BY r.id ORDER BY l.loaned_at DESC) AS rn
    FROM loans l
    JOIN readers r ON r.id = l.reader_id
    JOIN books b   ON b.id = l.book_id
)
SELECT full_name, title, loaned_at
FROM ranked
WHERE rn = 1
ORDER BY full_name;
~~~

~~~text
   full_name   |          title           | loaned_at
---------------+--------------------------+------------
 Анна Иванова  | Преступление и наказание | 2026-09-20
 Борис Петров  | Двенадцать стульев       | 2026-10-01
 Вера Смирнова | Мастер и Маргарита       | 2026-10-02
~~~
:::

:::spoiler Ответ к 27
~~~sql
WITH monthly AS (
    SELECT date_trunc('month', loaned_at)::date AS month, count(*) AS loans
    FROM loans
    GROUP BY 1
)
SELECT month, loans, sum(loans) OVER (ORDER BY month) AS running_total
FROM monthly
ORDER BY month;
~~~

~~~text
   month    | loans | running_total
------------+-------+---------------
 2026-08-01 |     1 |             1
 2026-09-01 |     4 |             5
 2026-10-01 |     2 |             7
~~~

Сначала агрегируем в CTE, потом применяем окно. Попытка сделать всё в одном запросе (`sum(count(*)) OVER (ORDER BY date_trunc(..., loaned_at))`) упадёт с ошибкой: в окне можно ссылаться только на сгруппированные выражения.
:::

## Что меняется по сравнению с Фазой 2

| Было (Фаза 2) | Стало (Фаза 3) |
|---|---|
| Списки в памяти + JSON | PostgreSQL + EF Core |
| `Dictionary` как индекс | индексы и `UNIQUE` в базе |

## Граничные случаи

- [ ] Дубликат ISBN: ошибка уникальности из базы (`DbUpdateException`) превращается в понятное доменное сообщение
- [ ] Удаление читателя с выдачами запрещено (`Restrict`) — понятное сообщение, а не трассировка исключения
- [ ] Две параллельные выдачи последнего экземпляра (запусти две консоли) — выдаётся только одна
- [ ] Импорт с битой записью: транзакция откатывается целиком или битые записи пропускаются с отчётом — реши и опиши
- [ ] Пустая база при первом запуске — понятная подсказка «примените миграции» или авто-применение по флагу

## Подсказки

:::spoiler Атомарная выдача без гонки
~~~csharp
public Loan IssueBook(int bookId, int readerId, DateOnly today)
{
    using var tx = _db.Database.BeginTransaction();

    // Блокируем строку книги до конца транзакции: параллельная выдача этой книги подождёт.
    var book = _db.Books
        .FromSqlInterpolated($"SELECT * FROM \"Books\" WHERE \"Id\" = {bookId} FOR UPDATE")
        .SingleOrDefault() ?? throw new LibraryException("Книга не найдена");

    int onHand = _db.Loans.Count(l => l.BookId == bookId && l.ReturnedAt == null);
    if (onHand >= book.Copies) throw new LibraryException("Свободных экземпляров нет");

    var loan = new Loan { BookId = bookId, ReaderId = readerId, LoanedAt = today, DueAt = today.AddDays(14) };
    _db.Loans.Add(loan);
    _db.SaveChanges();
    tx.Commit();
    return loan;
}
~~~

`FromSqlInterpolated` превращает интерполированные значения в **параметры SQL**, а не вклеивает их в строку, — это защита от SQL-инъекций. Никогда не собирай SQL конкатенацией с пользовательским вводом.
:::

:::spoiler Ошибка уникальности → доменное сообщение
~~~csharp
try
{
    _db.SaveChanges();
}
catch (DbUpdateException ex) when (ex.InnerException is Npgsql.PostgresException { SqlState: "23505" })
{
    // 23505 — код PostgreSQL для нарушения уникальности
    throw new LibraryException("Книга с таким ISBN уже есть", ex);
}
~~~

Проверка «есть ли такой ISBN» в C# перед вставкой полезна для понятного сообщения, но **не защищает от гонки**. Защищает уникальный индекс в базе.
:::
