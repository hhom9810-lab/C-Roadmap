Здесь глубина почти полностью уступает место завершённости. Это осознанный компромисс: рынку нужен готовый продукт в портфолио, а не ещё один слой понимания. Капстоун должен быть доступен по ссылке, которую можно отправить живому человеку.
:::

:::info Пропорция фазы
**10% теории / 20% практики / 70% проекта**. Теория здесь — ровно то, что нужно для деплоя капстоуна и для собеседований. Алгоритмы: 3–4 задачи в неделю, системно, с упором на паттерны решений.
:::

## Границы фазы {#borders}

:::deep Что НЕ входит в эту фазу
Kubernetes, микросервисы, распределённые транзакции, глубокий DevOps, оптимизация производительности до микросекунд — **не нужно**. Капстоун — хорошо сделанный монолит. Это сильнее, чем недоделанные микросервисы.
:::

## Практика фазы

- LeetCode/аналоги — системно, 3–4 задачи в неделю, с упором на паттерны решений
- Разбор 10–15 реальных вакансий junior .NET: выписать повторяющиеся требования, закрыть пробелы точечно

## Капстоун

Один финальный, самый крупный и отполированный проект: слоистая архитектура, EF Core + миграции, аутентификация, тесты (unit + интеграционные), Docker, CI/CD, деплой по ссылке, README с диаграммами. Тема — та, что реально цепляет → [техзадание](#p6-capstone).

## Критерий готовности {#criteria}

:::criteria Критерий готовности к фазе 7
- [ ] Капстоун задеплоен и доступен по публичной ссылке дольше недели без падений
- [ ] Решено минимум 100–120 алгоритмических задач суммарно за весь путь
- [ ] Есть 3–4 презентабельных проекта в GitHub с нормальными README, не только капстоун
:::
