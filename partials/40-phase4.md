:::info Пропорция фазы
**20% теории / 35% практики / 45% проекта**. Каждую тему закрепляй **сразу на живом API проекта**, а не на изолированных примерах из туториала. Создай проект в первую неделю и наращивай его тема за темой.
:::

## Границы фазы {#borders}

:::deep Что НЕ входит в эту фазу
Внутренности Kestrel, написание собственного DI-контейнера, OAuth 2.0 / OpenID Connect с внешним провайдером, микросервисы, gRPC, SignalR, CQRS с MediatR «по полной» — **не сейчас**. Цель — уверенный монолитный REST API с чистой структурой.
:::

## Практика фазы

- Каждую тему закреплять на живом API, а не на изолированных примерах
- Читать чужой код на GitHub (open-source ASP.NET Core проекты) хотя бы раз в 2 недели: как устроены папки, как зарегистрированы сервисы, как обрабатываются ошибки. Веди заметки «что подсмотрел»

## Проект фазы (первый серьёзный, для портфолио)

Полноценный REST API — например, **Task management / Job board / небольшой e-commerce backend**: многослойная архитектура, EF Core + миграции + PostgreSQL, JWT с ролями, валидация, глобальная обработка ошибок, логирование, базовые unit-тесты, README с архитектурой и инструкцией запуска → [техзадание](#p4-project).

## Критерий готовности {#criteria}

:::criteria Критерий готовности к фазе 5
- [ ] API имеет минимум 4–5 сущностей со связями, полноценный CRUD + бизнес-логику сверх CRUD (не просто «сохранить в базу»)
- [ ] Можешь объяснить разницу Scoped/Transient/Singleton на конкретном баге, который у тебя из-за этого случался
- [ ] Проект запускается хотя бы локально в Docker-контейнере одной командой
- [ ] Написан минимум 1 полноценный README с архитектурной схемой (можно от руки или в draw.io)
:::
