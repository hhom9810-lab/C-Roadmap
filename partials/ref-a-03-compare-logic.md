@@ref id="op-comparison" cat="A" title="Операторы сравнения (== != < > <= >=)" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="сравнение равенство == != больше меньше reference equality value equality строки ReferenceEquals Equals is null nullable кортежи" topic="p1-types,p1-syntax,p2-dictionary" related="op-float-special,op-is-as,op-pattern-relational,op-overloading" learn="dotnet/csharp/language-reference/operators/equality-operators::Операторы равенства"
Операторы сравнения возвращают `bool`; смысл `==` зависит от типа: для значений — равенство содержимого, для большинства ссылочных типов — тождество объектов, а для `string` и записей — равенство по значению.

## Синтаксис {#syntax}

~~~csharp @nocheck
a == b    a != b            // равенство и неравенство
a < b     a > b             // строго меньше / больше
a <= b    a >= b            // нестрого
(1, "x") == (1, "x")        // кортежи: поэлементно
x is null    x is not null  // проверка на null без пользовательского ==
~~~

## Семантика {#semantics}

- **Числа.** Операнды повышаются до общего типа ([арифметика](#/ref/a/op-arithmetic)), потом сравниваются. С `NaN` все сравнения, кроме `!=`, ложны ([подробнее](#/ref/a/op-float-special)).
- **Структуры.** Для собственной `struct` оператор `==` **не определён**, пока вы его не перегрузите (у `record struct` он генерируется компилятором). Для `enum` сравнение идёт по базовому числу.
- **Ссылочные типы.** По умолчанию `==` — тождество: две ссылки равны, только если указывают на один объект. Исключения: `string`, записи (`record`) и типы с перегруженным `==`.
- **`string`.** `==` сравнивает содержимое посимвольно и регистрозависимо (ordinal). Операторов `<` и `>` для строк нет: для порядка используйте `string.Compare` или `string.CompareOrdinal`.
- **Тип определяется статически.** Если обе переменные объявлены как `object`, `==` — это сравнение ссылок, даже если внутри лежат равные строки или упакованные числа.
- **`Nullable<T>`.** Операторы «подняты»: `null == null` истинно, `null == 3` ложно, а `<`, `>`, `<=`, `>=` с `null` всегда ложны.
- **Кортежи.** С C# 7.3 `==` и `!=` сравнивают кортежи поэлементно, слева направо, с остановкой на первом отличии.

## Под капотом {#internals}

Для чисел компилятор выдаёт `ceq`, `cgt`, `clt` (а `<=` — как `!(a > b)` для целых; для вещественных с учётом `NaN` — отдельные варианты `cgt.un`/`clt.un`), либо сразу инструкции перехода `beq`, `blt` и т. п., когда сравнение стоит в условии. Для `string ==` вызывается `string.op_Equality`: сначала проверка ссылок и длин, затем векторизованное сравнение буферов. Для `object ==` — сравнение указателей.

## Сложность {#complexity}

Числа и ссылки: `O(1)`. Строки: `O(n)` в худшем случае (равные по длине и по содержимому), но `O(1)`, если ссылки совпали или длины различаются.

## Версии {#versions}

- C# 1.0 — базовые операторы.
- C# 7.3 — `==`/`!=` для кортежей.
- C# 8 — шаблоны позволяют писать `x is null` и сравнения `x is > 5` ([реляционные шаблоны](#/ref/a/op-pattern-relational) — C# 9).
- C# 9 — записи: равенство по значению генерируется автоматически.
- C# 11 — операторы равенства можно требовать в обобщённом коде через `IEqualityOperators<,,>`.

## Ловушки {#pitfalls}

**Сравнение упакованных значений.**

~~~csharp
object a = 1, b = 1;
Console.WriteLine(a == b);        // ❌ False: сравниваются ссылки на две коробки
Console.WriteLine(a.Equals(b));   // ✅ True

object s1 = "ab", s2 = new string("ab".AsSpan());
Console.WriteLine(s1 == s2);      // ❌ False: статический тип object — ссылки
Console.WriteLine((string)s1 == (string)s2);   // ✅ True
~~~
~~~console
False
True
False
True
~~~

**Равенство вещественных** — только с допуском ([NaN и Infinity](#/ref/a/op-float-special)).

**Сравнение с `null` при перегруженном `==`.** `x == null` вызовет пользовательский оператор, а он может вести себя нетривиально; `x is null` всегда проверяет ссылку.

**Строки и регистр.** `"A" == "a"` ложно; для регистронезависимого сравнения — `string.Equals(a, b, StringComparison.OrdinalIgnoreCase)`.

## Примеры {#examples}

~~~csharp
Console.WriteLine(7 == 7.0);                  // True: int → double
Console.WriteLine("abc" == "ab" + "c");       // True: сравнение содержимого
Console.WriteLine(ReferenceEquals("abc", new string("abc".AsSpan())));   // False

int? n = null;
Console.WriteLine(n == null);                 // True
Console.WriteLine(n < 5);                     // False
Console.WriteLine(n >= 5);                    // False: и «меньше», и «не меньше» ложны

Console.WriteLine((1, "x") == (1, "x"));      // True
Console.WriteLine(string.CompareOrdinal("a", "b") < 0);   // True
~~~
~~~console
True
True
False
True
False
False
True
True
~~~

@@ref id="op-logical" cat="A" title="Логические операторы (&&, ||, !, &, |, ^)" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="логические && || ! & | ^ короткое замыкание short-circuit булевы bool? троичная логика XOR" topic="p1-syntax" related="op-bitwise,op-comparison,op-eval-order,op-null-conditional" learn="dotnet/csharp/language-reference/operators/boolean-logical-operators::Логические операторы"
Логические операторы комбинируют значения типа `bool`; `&&` и `||` вычисляют правый операнд только при необходимости (короткое замыкание), а `&`, `|` и `^` всегда вычисляют оба.

## Синтаксис {#syntax}

~~~csharp @nocheck
!a          // отрицание
a && b      // И с коротким замыканием
a || b      // ИЛИ с коротким замыканием
a & b       // И без короткого замыкания
a | b       // ИЛИ без короткого замыкания
a ^ b       // исключающее ИЛИ
a &= b;  a |= b;  a ^= b;    // составные формы (операторов &&= и ||= в C# нет)
~~~

## Семантика {#semantics}

- `a && b`: если `a` ложно, результат ложен и `b` **не вычисляется**. `a || b`: если `a` истинно, `b` не вычисляется.
- `a & b`, `a | b`, `a ^ b` на `bool` вычисляют **оба** операнда слева направо. Это нужно, когда у правой части есть побочный эффект, который должен выполниться всегда, но чаще это источник ошибок.
- Для целых типов те же символы `&`, `|`, `^` — [побитовые операторы](#/ref/a/op-bitwise).
- **Приоритет:** `!` выше `&`, выше `^`, выше `|`, выше `&&`, выше `||`. Отсюда `a || b && c` — это `a || (b && c)`. Скобки лучше любого запоминания.
- **`bool?` (трёхзначная логика).** `&` и `|` определены с учётом `null`: `null & false` — `false`, `null | true` — `true`, иначе результат `null`. Операторов `&&` и `||` для `bool?` нет.
- Тип с перегруженными `true`/`false` и `&`/`|` может участвовать в `&&` и `||`; это редкий приём.

## Под капотом {#internals}

`a && b` компилируется в условный переход: IL проверяет `a` (`brfalse`) и пропускает вычисление `b`. `a & b` для `bool` — одна инструкция `and`: оба значения уже на стеке. JIT вправе превратить короткое замыкание в безветвевой код, если правая часть не имеет побочных эффектов и дёшева — семантика при этом сохраняется. Для условий в `if` компилятор не создаёт промежуточных `bool`, а строит цепочку переходов напрямую.

## Сложность {#complexity}

`O(1)`. Выигрыш короткого замыкания — в пропуске дорогой правой части: ставьте дешёвые и чаще ложные условия слева. Ветвление может сбивать предсказатель переходов; в узких циклах иногда `&` быстрее `&&` — но только профилировщик это подтвердит.

## Версии {#versions}

- C# 1.0 — все операторы кроме `bool?`-логики.
- C# 2.0 — `bool?` и `&`/`|` над `Nullable<bool>`.
- C# 9 — ключевые слова `and`, `or`, `not` в [шаблонах](#/ref/a/op-pattern-relational) (это не операторы над `bool`, а комбинаторы шаблонов).

## Ловушки {#pitfalls}

**`&` вместо `&&` в защитных проверках.**

~~~csharp
string s = null;
try { if (s != null & s.Length > 0) Console.WriteLine("не пусто"); }   // ❌ оба операнда вычисляются
catch (NullReferenceException) { Console.WriteLine("NRE: использован &"); }

if (s != null && s.Length > 0) Console.WriteLine("не пусто");          // ✅ правая часть пропущена
else Console.WriteLine("пусто или null");
~~~
~~~console
NRE: использован &
пусто или null
~~~

**Побочный эффект в правой части.** В `if (Check() || Save())` метод `Save()` вызывается не всегда; в `if (Check() | Save())` — всегда. Читатель кода редко держит это в голове.

**Приоритет `&&` и `||`.** `a || b && c` читают как `(a || b) && c`, а это не так.

**Сравнение `bool` с `true`.** `if (flag == true)` избыточно; для `bool?` же нужна явная форма: `if (flag == true)` проверяет «`true`, а не `null`».

## Примеры {#examples}

~~~csharp
static bool Log(string name, bool value) { Console.WriteLine("вычислено " + name); return value; }

Console.WriteLine(Log("a", false) && Log("b", true));    // b пропущено
Console.WriteLine(Log("a", true) || Log("b", true));     // b пропущено
Console.WriteLine(Log("a", false) & Log("b", true));     // вычислены оба
Console.WriteLine(true ^ true);                          // False

bool? n = null;
Console.WriteLine(n & false);       // False
Console.WriteLine(n | true);        // True
Console.WriteLine(n & true);        // (пусто: null)
Console.WriteLine(true || false && false);   // True: && сильнее ||
~~~
~~~console
вычислено a
False
вычислено a
True
вычислено a
вычислено b
False
False
False
True

True
~~~

@@ref id="op-bitwise" cat="A" title="Побитовые операторы (&, |, ^, ~) и флаги" cs="1.0" cx="O(1)" mem="O(1)" tags="побитовые битовые маски флаги Flags and or xor not BitOperations PopCount HasFlag маска биты" topic="p1-types,p1-syntax" related="op-shift,op-logical,op-arithmetic" learn="dotnet/csharp/language-reference/operators/bitwise-and-shift-operators::Побитовые операторы и операторы сдвига"
Побитовые операторы применяют логическую операцию к каждой паре разрядов целых чисел сразу: `&` — И, `|` — ИЛИ, `^` — исключающее ИЛИ, `~` — инверсия всех разрядов.

## Синтаксис {#syntax}

~~~csharp @nocheck
a & b     // 1, если оба разряда 1
a | b     // 1, если хотя бы один разряд 1
a ^ b     // 1, если разряды различаются
~a        // инверсия каждого разряда
a &= b;  a |= b;  a ^= b;      // составные формы
~~~

Операторы определены для `int`, `uint`, `long`, `ulong` и (через повышение до `int`) для `byte`, `sbyte`, `short`, `ushort`, `char`; также для `enum` и `bool` (логические варианты — в [записи о логических операторах](#/ref/a/op-logical)).

## Семантика {#semantics}

- Операнды повышаются до `int` или шире ([числовое повышение](#/ref/a/op-arithmetic)). Поэтому `~b` для `byte b = 5` — это `int` со значением `-6`, а не `250`.
- Смешивать `int` (знаковое) и `ulong` нельзя; со знаковыми отрицательными константами будьте осторожны из-за знакового расширения.
- Для знаковых целых используется дополнительный код: `~x == -x - 1`, `-1` — все биты единицы.
- **Флаги.** Перечисление с `[Flags]` хранит набор значений в битах: добавить — `|=`, убрать — `&= ~F`, переключить — `^=`, проверить — `(x & F) == F` или `x.HasFlag(F)`.
- **Типичные приёмы:** `x & (x - 1)` сбрасывает младший установленный бит; `x & -x` выделяет его; `(x & 1) == 0` — проверка чётности; `x & mask` — извлечение поля.

## Под капотом {#internals}

Каждый оператор — одна IL-инструкция (`and`, `or`, `xor`, `not`) и одна машинная инструкция процессора. `HasFlag` в современных версиях .NET JIT разворачивает в побитовую проверку без упаковки. Для подсчёта битов, поиска старшего и младшего бита есть `System.Numerics.BitOperations` (`PopCount`, `LeadingZeroCount`, `TrailingZeroCount`), а с .NET 7 — те же методы как `int.PopCount(x)`; они компилируются в аппаратные инструкции.

## Сложность {#complexity}

`O(1)` и очень быстро. Массивы битов (`BitArray`, `ulong[]`) позволяют обрабатывать 64 флага одной инструкцией.

## Версии {#versions}

- C# 1.0 — `&`, `|`, `^`, `~`.
- .NET Core 2.1 — `Enum.HasFlag` перестал упаковывать значения (JIT-оптимизация; точная версия — требует проверки).
- .NET Core 3.0 — класс `BitOperations`.
- .NET 7 — `int.PopCount` и другие через обобщённую математику; C# 11 — `>>>` ([сдвиги](#/ref/a/op-shift)).

## Ловушки {#pitfalls}

**Приоритет побитовых и сравнений.** `x & 1 == 0` читается как `x & (1 == 0)` и не компилируется (`int & bool`); нужны скобки: `(x & 1) == 0`.

**Знаковое расширение.** `byte b = 0xF0; int r = ~b & 0xFF;` — без `& 0xFF` получится отрицательное число.

**`HasFlag` с нулевым значением.** `x.HasFlag(Flags.None)` всегда `true`, потому что `None = 0`.

**Перечисление без `[Flags]` и степеней двойки.** Значения `1, 2, 3` пересекаются по битам: `3 = 1 | 2`.

## Примеры {#examples}

~~~csharp
static string Bin(int v) => Convert.ToString(v, 2).PadLeft(8, '0');

int a = 0b1100, b = 0b1010;
Console.WriteLine(Bin(a & b));   // 00001000
Console.WriteLine(Bin(a | b));   // 00001110
Console.WriteLine(Bin(a ^ b));   // 00000110
Console.WriteLine(~5);           // -6

byte small = 5;
Console.WriteLine(~small);               // -6 (тип int)
Console.WriteLine((byte)~small);         // 250

var p = Perm.Read | Perm.Write;
p |= Perm.Exec;                           // добавить
p &= ~Perm.Write;                         // убрать
Console.WriteLine(p);                     // Read, Exec
Console.WriteLine((p & Perm.Read) != 0);  // True

int x = 0b101100;
Console.WriteLine(Bin(x & (x - 1)));     // 00101000: младшая единица сброшена
Console.WriteLine(int.PopCount(x));      // 3

[Flags] enum Perm { None = 0, Read = 1, Write = 2, Exec = 4 }
~~~
~~~console

00001110
00000110
-6
-6
250
Read, Exec
True
00101000
3
~~~

@@ref id="op-shift" cat="A" title="Операторы сдвига (<<, >>, >>>)" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="сдвиг shift << >> >>> арифметический логический маска счётчика сдвига умножение на степень двойки" topic="p1-types,p1-syntax" related="op-bitwise,op-division,op-arithmetic" learn="dotnet/csharp/language-reference/operators/bitwise-and-shift-operators::Операторы сдвига"
Операторы сдвига смещают разряды числа влево или вправо на заданное количество позиций; сдвиг влево на `n` — умножение на `2ⁿ`, а сдвиг вправо — деление на `2ⁿ` с округлением вниз.

## Синтаксис {#syntax}

~~~csharp @nocheck
x << n     // сдвиг влево, справа нули
x >> n     // сдвиг вправо: арифметический для знаковых, логический для беззнаковых
x >>> n    // беззнаковый (логический) сдвиг вправо — C# 11
x <<= n;   x >>= n;   x >>>= n;
~~~

## Семантика {#semantics}

- Левый операнд — `int`, `uint`, `long` или `ulong` (меньшие типы повышаются до `int`), правый — `int`.
- **Счётчик сдвига маскируется:** для 32-битных типов используются младшие 5 бит (`n & 31`), для 64-битных — 6 бит (`n & 63`). Поэтому `1 << 32` равно `1`, а не `0`; `1 << -1` равно `1 << 31`.
- Результат сдвига `int` — снова `int`; чтобы получить 64-битное значение, начинайте с `long`: `1L << 40`. Счётчик сдвига должен быть `int` или приводиться к нему.
- `<<` отбрасывает старшие биты без проверки: контекст `checked` на сдвиги **не влияет**.
- `>>` для знаковых типов **арифметический**: копирует знаковый бит, поэтому `-8 >> 1` равно `-4`. Для `uint`/`ulong` — логический, старшие разряды заполняются нулями.
- `>>>` всегда заполняет старшие разряды нулями, в том числе для знаковых типов: `-8 >>> 1` равно `2147483644`.
- Сдвиг вправо округляет **вниз** (к минус бесконечности), а деление `/` — к нулю: `-7 >> 1 == -4`, `-7 / 2 == -3`.

## Под капотом {#internals}

IL: `shl`, `shr` (знаковый), `shr.un` (беззнаковый). Маскирование счётчика соответствует поведению x86 (`shl` сам берёт младшие 5/6 бит), поэтому JIT не добавляет проверку. Оператор `>>>` для знаковых типов компилируется в `shr.un`. Умножение и деление на константы-степени двойки JIT сам заменяет сдвигами, писать их вручную ради скорости не нужно (для деления знакового числа потребуется дополнительная поправка, чтобы сохранить округление к нулю).

## Сложность {#complexity}

`O(1)`, одна инструкция процессора.

## Версии {#versions}

- C# 1.0 — `<<`, `>>`.
- C# 11 / .NET 7 — оператор `>>>`, `<<` и `>>` для пользовательских типов с правым операндом любого типа (раньше правый операнд пользовательского оператора обязан быть `int`).

## Ловушки {#pitfalls}

**Сдвиг на число, не меньшее разрядности.**

~~~csharp
int n = 32;
Console.WriteLine(1 << n);          // ❌ 1, а не 0: счётчик маскируется (32 & 31 = 0)
Console.WriteLine(1L << n);         // ✅ 4294967296 для long
Console.WriteLine(1 << 31);         // -2147483648: единица попала в знаковый бит
~~~
~~~console
1
4294967296
-2147483648
~~~

**`>>` на знаковых отрицательных** сохраняет знак; для логического сдвига используйте `>>>` или беззнаковые типы.

**Замена деления сдвигом.** `x >> 1` и `x / 2` одинаковы для неотрицательных, но различаются для отрицательных нечётных чисел.

**Приоритет.** Сдвиги слабее `+` и `-`, но сильнее сравнений: `1 << 2 + 1` — это `1 << 3`.

## Примеры {#examples}

~~~csharp
Console.WriteLine(3 << 2);          // 12
Console.WriteLine(-8 >> 1);         // -4
Console.WriteLine(-8 >>> 1);        // 2147483644
Console.WriteLine(-7 >> 1);         // -4
Console.WriteLine(-7 / 2);          // -3
Console.WriteLine(0xF0u >> 4);      // 15

uint packed = (0xAAu << 24) | (0xBBu << 16) | (0xCCu << 8) | 0xDDu;   // упаковка 4 байт
Console.WriteLine(packed.ToString("X8"));        // AABBCCDD
Console.WriteLine((packed >> 16) & 0xFF);        // 187 (0xBB): извлечение поля
Console.WriteLine(1 << 2 + 1);                   // 8
~~~
~~~console
12
-4
2147483644
-4
-3
15
AABBCCDD
187
8
~~~

@@ref id="op-assignment" cat="A" title="Присваивание и составные присваивания" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="присваивание += -= *= /= составное assignment compound swap деконструкция ref assignment events подписка" topic="p1-syntax" related="op-incdec,op-null-coalescing,op-overloading,op-eval-order" learn="dotnet/csharp/language-reference/operators/assignment-operator::Оператор присваивания"
Оператор `=` записывает значение правой части в переменную, свойство или индексатор, а составные формы вроде `+=` сокращают запись `a = a + b` и вычисляют левую часть один раз.

## Синтаксис {#syntax}

~~~csharp @nocheck
x = expr;                       // простое присваивание
x += y;  x -= y;  x *= y;  x /= y;  x %= y;
x &= y;  x |= y;  x ^= y;  x <<= y;  x >>= y;  x >>>= y;
x ??= y;                        // присвоить, если x равен null
(a, b) = (b, a);                // присваивание кортежем (обмен)
ref int r = ref arr[0];         // ref-локальная переменная
r = ref arr[1];                 // переназначение ссылки (C# 7.3)
button.Click += Handler;        // подписка на событие
~~~

## Семантика {#semantics}

- Присваивание — **выражение**: его значение равно присвоенному, поэтому допустимо `a = b = 0;` (правая ассоциативность: `a = (b = 0)`).
- `x op= y` означает `x = (T)(x op y)`, но **`x` вычисляется один раз**, а результат явно приводится к типу `x` — при условии, что `y` неявно преобразуется к `T` (или операция — сдвиг). Поэтому `b += 1` для `byte b` компилируется, а `b = b + 1` — нет. А вот `i *= 1.5` для `int i` — ошибка CS0266: `double` не преобразуется к `int` неявно.
- Для `a[i++] += 2` индексное выражение вычисляется один раз; для свойства геттер и сеттер вызываются по одному разу.
- Для делегатов и событий `+=` и `-=` означают добавление и удаление обработчика, для строк `+=` — [конкатенацию](#/ref/a/op-string-concat) с созданием новой строки.
- Присваивание кортежем сначала вычисляет всю правую часть, потом присваивает: `(a, b) = (b, a)` корректно меняет значения местами.
- Присваивание `readonly`-полям допустимо только в конструкторе, `init`-свойствам — в инициализаторе объекта и конструкторе.
- Для типов-значений присваивание **копирует** значение, для ссылочных — копирует ссылку.

## Под капотом {#internals}

Для локальной переменной составное присваивание превращается в `ldloc; <операнд>; add; stloc`. Для цепочки `a = b = c` компилятор добавляет `dup`. Для свойства: `callvirt get_X`, операция, `callvirt set_X`. Для поля структуры, к которому обращаются через значение, а не через ссылку, присваивание изменит копию — отсюда ошибка CS1612 при попытке изменить поле структуры, возвращённой свойством.

## Сложность {#complexity}

`O(1)`; для структур — `O(размер структуры)` (копирование). `s += x` для строк — `O(длина)`, см. [конкатенацию](#/ref/a/op-string-concat).

## Версии {#versions}

- C# 1.0 — `=` и составные операторы.
- C# 7.0 — присваивание кортежем и деконструкция; ref-локальные переменные.
- C# 7.3 — переназначение `ref`-локальных (`r = ref other`).
- C# 8 — `??=` ([подробнее](#/ref/a/op-null-coalescing)).
- C# 11 — `>>>=`.
- C# 14 — можно объявлять пользовательские составные операторы (`public void operator +=(T other)`), которые изменяют объект на месте.

## Ловушки {#pitfalls}

**Присваивание вместо сравнения.** `if (a = b)` скомпилируется только если `a` — `bool`; в `if (flag = true)` условие всегда истинно, а компилятор лишь предупредит.

**Составное присваивание скрывает переполнение.**

~~~csharp
byte b = 250;
b += 10;                  // ❌ компилируется: (byte)(250 + 10) = 4, без предупреждения
Console.WriteLine(b);
int i = 10;
i = (int)(i * 1.5);       // дробную часть отбрасывает явное приведение
Console.WriteLine(i);
~~~
~~~console
4
15
~~~

**Изменение копии структуры.** Если свойство возвращает структуру, `obj.Point.X = 5` изменит копию — компилятор запретит такую запись (CS1612).

**Захват переменной в лямбду.** Присваивание внутри лямбды меняет захваченную переменную снаружи.

## Примеры {#examples}

~~~csharp
int a, b, c;
a = b = c = 7;
Console.WriteLine(a + b + c);          // 21

int x = 1, y = 2;
(x, y) = (y, x);
Console.WriteLine($"{x} {y}");         // 2 1

var arr = new[] { 1, 2, 3 };
ref int r = ref arr[0];
r = 100;                               // записали в arr[0]
r = ref arr[1];
r = 200;                               // теперь пишем в arr[1]
Console.WriteLine(string.Join(",", arr));   // 100,200,3

string s = "ab";
s += "cd";
Console.WriteLine(s);                  // abcd

int calls = 0;
int[] data = new int[3];
int Index() { calls++; return 1; }
data[Index()] += 5;                    // Index() вызывается один раз
Console.WriteLine($"{data[1]} {calls}");   // 5 1
~~~
~~~console
21
2 1
100,200,3
abcd
5 1
~~~
