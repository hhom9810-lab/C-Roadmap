@@ref id="op-incdec" cat="A" title="Инкремент и декремент (++ и −−)" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="инкремент декремент префикс постфикс plus plus i++ ++i счётчик Interlocked" topic="p1-syntax" related="op-assignment,op-overflow,op-eval-order,op-overloading" learn="dotnet/csharp/language-reference/operators/arithmetic-operators::Операторы инкремента и декремента"
Операторы `++` и `--` увеличивают или уменьшают переменную на единицу; в префиксной форме выражение даёт новое значение, в постфиксной — старое.

## Синтаксис {#syntax}

~~~csharp @nocheck
++x;   --x;      // префиксная форма: сначала изменить, потом вернуть новое значение
x++;   x--;      // постфиксная форма: вернуть старое значение, потом изменить
~~~

Операнд должен быть переменной, свойством или индексатором (то, чему можно присвоить значение); `5++` или `(a + b)++` не скомпилируются.

## Семантика {#semantics}

- `y = x++` — в `y` попадает **старое** `x`, затем `x` увеличивается. `y = ++x` — сначала `x` увеличивается, в `y` попадает новое.
- Если результат выражения не используется (`i++;` как отдельная инструкция), обе формы эквивалентны.
- Операнд вычисляется один раз. Для `arr[Next()]++` метод `Next()` вызывается единожды: компилятор запоминает индекс, читает элемент, увеличивает и записывает обратно.
- Работают для всех числовых типов, `char` и перечислений (для `enum` — над базовым типом). Для `byte`/`short` результат неявно приводится обратно к исходному типу, поэтому `b++` компилируется, хотя `b = b + 1` — нет.
- Для типов с перегруженным `++` вызывается пользовательский оператор (см. [перегрузка операторов](#/ref/a/op-overloading)).
- Выражение вроде `x = x++` **ничего не меняет**: `x++` вернул старое значение и увеличил `x`, но присваивание затем вернуло старое значение обратно.

## Под капотом {#internals}

Для локальной переменной `i++` как отдельной инструкции превращается в `ldloc i; ldc.i4.1; add; stloc i`. Если значение выражения нужно, компилятор добавляет `dup`, чтобы сохранить старое (постфикс) или новое (префикс) значение на стеке.

Операция **не атомарна**: это чтение, сложение и запись. Из нескольких потоков общий счётчик надо увеличивать через `Interlocked.Increment`. Для свойств `p++` превращается в вызов геттера, сложение и вызов сеттера — побочные эффекты геттера и сеттера выполнятся один раз каждый.

## Сложность {#complexity}

`O(1)`. Разницы между `++i` и `i++` в скорости для встроенных типов нет: JIT выдаёт один и тот же код. Для пользовательских типов постфиксная форма может создавать копию старого значения, поэтому в циклах по итераторам-структурам предпочитают префиксную.

## Версии {#versions}

- C# 1.0 — обе формы.
- C# 11 — `checked`-версии пользовательских `++` и `--`.
- C# 14 — пользовательские `++`/`--` (и составные присваивания) можно объявлять **экземплярными** методами `public void operator ++()`, которые изменяют объект на месте, без создания копии.

## Ловушки {#pitfalls}

**Использовать переменную и её же инкремент в одном выражении.**

~~~csharp
int i = 1;
int x = i + i++;     // ⚠ читается слева направо: 1 + 1, потом i = 2
int y = i++ + i;     // 2 + 3: старое значение, потом уже увеличенное
Console.WriteLine($"{x} {y} {i}");

int k = 5;
k = k++;             // ❌ k остался 5
Console.WriteLine(k);
~~~
~~~console
2 5 3
5
~~~

Читаемый код избегает таких выражений: инкремент выносят в отдельную строку. Подробнее — в записи [порядок вычисления операндов](#/ref/a/op-eval-order).

**Счётчик из нескольких потоков.** `count++` в параллельных задачах теряет обновления; используйте `Interlocked.Increment(ref count)`.

**Переполнение.** `int.MaxValue + 1` в `unchecked` контексте молча превращается в `int.MinValue`, то же верно для `++` (см. [checked и unchecked](#/ref/a/op-overflow)).

## Примеры {#examples}

~~~csharp
int a = 5;
Console.WriteLine(a++);   // 5, потом a = 6
Console.WriteLine(a);     // 6
Console.WriteLine(++a);   // 7
Console.WriteLine(--a);   // 6

var arr = new[] { 10, 20, 30 };
int i = 0;
arr[i++] += 1;            // индекс вычислен один раз: arr[0], затем i = 1
Console.WriteLine($"{string.Join(",", arr)} i={i}");

byte b = 255;
b++;                      // без checked: переполнение, 0
Console.WriteLine(b);

char c = 'a';
c++;
Console.WriteLine(c);     // b
~~~
~~~console
5
6
7
6
11,20,30 i=1
0
b
~~~

@@ref id="op-overflow" cat="A" title="Переполнение: checked и unchecked" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="переполнение checked unchecked OverflowException wraparound CheckForOverflowUnderflow целочисленное насыщение" topic="p1-types,p1-syntax" related="op-arithmetic,op-incdec,op-division,op-float-special,op-conversions" learn="dotnet/csharp/language-reference/statements/checked-and-unchecked::Инструкции checked и unchecked"
Целочисленная арифметика в .NET по умолчанию не проверяет переполнение и «заворачивается» по модулю разрядности, а `checked` включает проверку и бросает `OverflowException`.

## Синтаксис {#syntax}

~~~csharp @nocheck
int a = checked(x + y);          // выражение
checked { a = x * y; b = a + 1; } // блок
unchecked { a = x * y; }          // блок, явный отказ от проверки
a = unchecked((int)bigValue);     // выражение
~~~

Глобально проверка включается свойством проекта `<CheckForOverflowUnderflow>true</CheckForOverflowUnderflow>` (ключ компилятора `/checked+`).

## Семантика {#semantics}

- **Неконстантные выражения** по умолчанию вычисляются в `unchecked`: результат усекается до разрядности типа. `int.MaxValue + 1` на переменных даёт `int.MinValue`.
- **Константные выражения** проверяются **компилятором**: переполнение — ошибка CS0220 (арифметика) или CS0221 (приведение константы). Чтобы всё же записать такое значение, нужен `unchecked(...)`.
- В контексте `checked` переполнение `+`, `-`, `*`, унарного `-`, `++`, `--` и **явных** приведений между целыми типами бросает `OverflowException`.
- Область действия **лексическая**: `checked { ... }` влияет только на операции, записанные внутри блока, но не на вызываемые методы.
- На деление `int.MinValue / -1` контекст не влияет: оно бросает исключение всегда ([деление](#/ref/a/op-division)).
- `Math.Abs(int.MinValue)` бросает `OverflowException` независимо от контекста, потому что `+2147483648` в `int` не помещается. А вот унарный минус для `int.MinValue` в `unchecked` возвращает то же число.
- Преобразование вещественного числа в целое вне диапазона в `checked` бросает исключение. В `unchecked` результат зависит от версии рантайма: начиная с .NET 9 преобразования **насыщающие** (слишком большое → `MaxValue`, слишком малое → `MinValue`, `NaN` → `0`), раньше на x86/x64 результат был платформенно-зависимым.

## Под капотом {#internals}

В `checked`-контексте компилятор выдаёт `add.ovf`, `sub.ovf`, `mul.ovf` (для беззнаковых — `.ovf.un`) и `conv.ovf.*` вместо `add`, `sub`, `mul`, `conv.*`. JIT превращает их в обычную арифметическую инструкцию плюс условный переход по флагу переполнения (`jo`) на код, который бросает исключение. Дополнительной памяти не нужно.

## Сложность {#complexity}

`O(1)`. Накладные расходы `checked` — одна предсказуемая ветка на операцию; в вычислительных ядрах это заметно (иногда единицы процентов, иногда больше из-за мешающих векторизации проверок), в обычном прикладном коде — нет. Если проверка нужна не везде, включайте её точечно, а не глобально.

## Версии {#versions}

- C# 1.0 — `checked` и `unchecked`.
- C# 11 — можно объявлять собственные `checked`-операторы (`public static T operator checked +(T a, T b)`).
- .NET 9 — насыщающие преобразования `double`/`float` → целые на x86/x64 (см. выше).

## Ловушки {#pitfalls}

**Молчаливое переполнение в расчётах.**

~~~csharp
int price = 2_000_000, qty = 2_000;
int total = price * qty;              // ❌ молча: -294967296
long safe = (long)price * qty;        // ✅ расширяем до умножения
Console.WriteLine($"{total} {safe}");

try { int t = checked(price * qty); }
catch (OverflowException) { Console.WriteLine("переполнение поймано"); }
~~~
~~~console
-294967296 4000000000
переполнение поймано
~~~

**`checked` не заходит в вызовы.** `checked { return Compute(a, b); }` не включит проверку внутри `Compute`.

**Приведение константы.** `byte b = (byte)300;` не скомпилируется (CS0221), а `int n = 300; byte b = (byte)n;` даст `44` без ошибки.

**Хэши и счётчики.** Для хэш-кодов и контрольных сумм переполнение — штатная часть алгоритма: там пишут `unchecked`, чтобы код не ломался при включённом `/checked`.

## Примеры {#examples}

~~~csharp
int max = int.MaxValue;
Console.WriteLine(max + 1);                     // -2147483648 (unchecked по умолчанию)
Console.WriteLine(unchecked((byte)300));        // 44
int n = 300;
Console.WriteLine((byte)n);                     // 44

try { Console.WriteLine(checked((byte)n)); }
catch (OverflowException e) { Console.WriteLine(e.GetType().Name); }

try { Console.WriteLine(Math.Abs(int.MinValue)); }
catch (OverflowException e) { Console.WriteLine("Abs: " + e.GetType().Name); }

int result = 0;
try { checked { result = max; result++; } }
catch (OverflowException) { Console.WriteLine("result остался " + result); }
~~~
~~~console
-2147483648
44
44
OverflowException
Abs: OverflowException
result остался 2147483647
~~~

@@ref id="op-float-special" cat="A" title="NaN, Infinity и особенности вещественных чисел" cs="1.0" cx="O(1)" mem="O(1)" danger="1" tags="NaN Infinity бесконечность вещественные double float epsilon IsNaN отрицательный ноль сравнение вещественных точность IEEE 754" topic="p1-types,p1-syntax" related="op-arithmetic,op-division,op-comparison" learn="dotnet/api/system.double::Структура Double"
`float` и `double` следуют стандарту IEEE 754: кроме обычных чисел они хранят `+∞`, `-∞`, `NaN` («не число») и два нуля (`+0` и `-0`), а арифметика с ними не бросает исключений.

## Синтаксис {#syntax}

~~~csharp @nocheck
double.NaN   double.PositiveInfinity   double.NegativeInfinity
double.IsNaN(x)   double.IsInfinity(x)   double.IsFinite(x)
double.Epsilon   double.MaxValue   double.MinValue
~~~

## Семантика {#semantics}

- **Результат без исключений.** `1.0 / 0` — `Infinity`, `-1.0 / 0` — `-Infinity`, `0.0 / 0.0`, `Math.Sqrt(-1)`, `Infinity - Infinity` — `NaN`. Переполнение (`double.MaxValue * 2`) даёт `Infinity`.
- **`NaN` не равен ничему, даже самому себе:** `x == x` ложно, `x < y`, `x > y`, `x == y` — всё ложно, `x != y` — истинно. Проверять надо `double.IsNaN(x)`.
- **`Equals` и `CompareTo` ведут себя иначе, чем `==`:** `double.NaN.Equals(double.NaN)` — `true` (иначе сломались бы словари и сортировки), а `CompareTo` считает `NaN` меньше любого числа.
- **Два нуля:** `0.0 == -0.0` истинно, но `1 / -0.0` — `-Infinity`, а `ToString()` у `-0.0` вернёт `-0`.
- **Неточность двоичного представления.** `0.1` не представимо точно: `0.1 + 0.2` равно `0.30000000000000004`. Сравнивать вещественные на равенство нельзя — только с допуском.
- **`double.Epsilon` — не «машинный эпсилон».** Это наименьшее положительное денормализованное число (`≈ 4.9e-324`), использовать его как допуск при сравнении бессмысленно.
- **`float`** хранит около 7 десятичных значащих цифр, `double` — около 15–17: `16777217f == 16777216f`.
- **`decimal`** не имеет `NaN` и `Infinity`: деление на ноль бросает `DivideByZeroException`.

## Под капотом {#internals}

`double` — 64 бита: знак (1), порядок (11), мантисса (52). `float` — 32 бита (1/8/23). Значения вычисляются инструкциями FPU/SSE/AVX процессора; `NaN` и `Infinity` — просто особые битовые комбинации порядка. Поэтому арифметика над ними не исключительная ситуация, а обычная команда.

Деление на ноль для `int` проверяется JIT-кодом и бросает исключение, а для `double` аппаратно возвращает `Infinity` — вот источник разницы поведения.

## Сложность {#complexity}

`O(1)`. Денормализованные числа на некоторых процессорах обрабатываются медленнее (в горячих численных циклах это иногда замечают).

## Версии {#versions}

- C# 1.0 — `float`, `double`, `NaN`, `Infinity` в языке и библиотеке.
- .NET Core 3.0 — `double.IsFinite`, `IsNegative`, исправлена строгая соответствие IEEE 754 при разборе и форматировании (`ToString()` стал выдавать кратчайшую строку, которая округляется туда-обратно).
- .NET 7 — `double` реализует интерфейсы обобщённой математики (`IFloatingPointIeee754<double>` и другие), и вещественные числа можно использовать в обобщённом коде.

## Ловушки {#pitfalls}

**Сравнение на равенство.**

~~~csharp
double sum = 0.1 + 0.2;
Console.WriteLine(sum == 0.3);                       // ❌ False
Console.WriteLine(Math.Abs(sum - 0.3) < 1e-9);       // ✅ True: сравнение с допуском
Console.WriteLine(0.1m + 0.2m == 0.3m);              // ✅ для денег — decimal
~~~
~~~console
False
True
True
~~~

**Проверка на NaN через `==`:** `if (x == double.NaN)` всегда ложно — используйте `double.IsNaN(x)`.

**Деньги в `double`.** Накопленная ошибка округления приводит к «копейкам»; для денег — `decimal` или целые копейки.

**`NaN` в сортировке и `Min`/`Max`.** `NaN` «заражает» результат: `Math.Max(1, double.NaN)` — `NaN`. Отфильтруйте значения заранее.

## Примеры {#examples}

~~~csharp
double inf = 1.0 / 0, nan = 0.0 / 0.0;
Console.WriteLine($"{inf} {-inf} {nan}");
Console.WriteLine(nan == nan);                         // False
Console.WriteLine(double.IsNaN(nan));                  // True
Console.WriteLine(nan.Equals(nan));                    // True
Console.WriteLine(nan.CompareTo(1.0));                 // -1
Console.WriteLine(double.MaxValue * 2);                // Infinity
Console.WriteLine(0.0 == -0.0);                        // True
Console.WriteLine(1 / -0.0);                           // -Infinity
Console.WriteLine(0.1 + 0.2);                          // 0.30000000000000004
Console.WriteLine(16777217f == 16777216f);             // True
Console.WriteLine(double.Epsilon);                     // 5E-324
~~~
~~~console

~~~

@@ref id="op-string-concat" cat="A" title="Конкатенация строк: оператор + и его цена" cs="1.0" cx="O(n + m)" mem="O(n + m)" danger="1" tags="конкатенация строк plus string.Concat StringBuilder += в цикле интерполяция" topic="p1-strings" related="op-arithmetic,op-assignment" learn="dotnet/csharp/language-reference/operators/addition-operator::Оператор + и конкатенация строк"
Оператор `+` для строк создаёт новую строку, склеивая операнды; сами строки неизменяемы, поэтому каждая конкатенация копирует символы.

## Синтаксис {#syntax}

~~~csharp @nocheck
s1 + s2                 // строка + строка
"Итого: " + 42          // строка + любой объект → ToString()
s += "хвост";           // составная форма: новая строка и перезапись переменной
~~~

## Семантика {#semantics}

- Если один операнд — строка, второй приводится через `ToString()`; `null` превращается в пустую строку.
- `+` для `char` и `int` — это **сложение чисел**, а не строки: `'a' + 1` — `int` 98. Строкой выражение становится, только если слева (или рядом) уже есть `string`: `"" + 'a' + 1` → `"a1"`.
- Выражение вычисляется слева направо: `1 + 2 + "x"` — `"3x"`, а `"x" + 1 + 2` — `"x12"`.
- Склейка констант выполняется в компиляции: `"a" + "b"` превращается в литерал `"ab"` и интернируется.
- Для строк `+=` создаёт новую строку и записывает ссылку в переменную; старая строка становится мусором.

## Под капотом {#internals}

Компилятор переписывает цепочку `a + b + c` в один вызов `string.Concat(a, b, c)` — для 2–4 операндов есть перегрузки без массива, для большего числа используется перегрузка с массивом или `ReadOnlySpan<string>` (зависит от версии компилятора и целевой платформы). Поэтому **в одном выражении** цепочка из десятка слагаемых стоит одного выделения и копирования: промежуточные строки не создаются.

Стоимость каждого `Concat` — выделение строки длиной `n + m` и копирование обоих операндов. В цикле `s += x` на каждой итерации копируется вся накопленная строка: общая стоимость растёт квадратично, а нагрузка на GC — линейно по числу итераций.

## Сложность {#complexity}

Одна конкатенация: `O(n + m)` по времени и памяти. Конкатенация в цикле из `k` итераций: `O(k²)` по времени (для строки итоговой длины `~k`). `StringBuilder` и `string.Join` делают то же за `O(k)` амортизированно.

## Версии {#versions}

- C# 1.0 — `+` для строк.
- C# 6 — интерполяция `$"..."` (компилируется в `string.Format`).
- C# 10 / .NET 6 — интерполированные строки используют обработчики (`DefaultInterpolatedStringHandler`), которые пишут в буфер из пула без промежуточных аллокаций; интерполяция констант: `const string s = $"{A}{B}"`.
- C# 11 — многострочные выражения внутри `{}` интерполяции, сырые строковые литералы `"""..."""`.

## Ловушки {#pitfalls}

**`+=` в цикле.**

~~~csharp
using System.Text;

string slow = "";
for (int i = 0; i < 5; i++) slow += i + ",";          // ❌ на каждой итерации новая строка

var sb = new StringBuilder();
for (int i = 0; i < 5; i++) sb.Append(i).Append(',');  // ✅ один буфер
Console.WriteLine(slow == sb.ToString());
Console.WriteLine(string.Join(",", Enumerable.Range(0, 5)));   // ✅ ещё проще
~~~
~~~console
True
0,1,2,3,4
~~~

На пяти итерациях разницы не видно; на сотнях тысяч — видно по времени и по числу сборок мусора.

**`char + int`.** `Console.WriteLine('a' + 1)` печатает `98`, а не `a1`.

**Порядок слагаемых.** `Console.WriteLine("Сумма: " + 1 + 2)` печатает `Сумма: 12`; нужны скобки `1 + 2`.

## Примеры {#examples}

~~~csharp
string name = null;
Console.WriteLine("Привет, " + name + "!");   // null → пусто
Console.WriteLine("Сумма: " + 1 + 2);         // Сумма: 12
Console.WriteLine("Сумма: " + (1 + 2));       // Сумма: 3
Console.WriteLine('a' + 1);                   // 98
Console.WriteLine("" + 'a' + 1);              // a1
Console.WriteLine(1 + 2 + "x");               // 3x

const string A = "ab", B = "cd";
Console.WriteLine(ReferenceEquals(A + B, "abcd"));   // True: склейка констант в компиляции
~~~
~~~console
Привет, !
Сумма: 12
Сумма: 3
98
a1
3x
True
~~~
